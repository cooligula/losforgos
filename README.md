# losforgos: LineageOS apps for GrapheneOS

Builds the user-space LineageOS apps from upstream with GitHub Actions, signs them with one
stable key, and publishes them as GitHub releases that [Obtainium](https://github.com/ImranR98/Obtainium)
can track. Every app is installed as an ordinary app under the id `org.losforgos.<name>`;
nothing here is a system app.

## Install and update with Obtainium

Releases are per app and per variant. Add one Obtainium entry per app with:

- Source URL: this repository
- Filter release titles by regex: `^Glimpse ` (the app's title, plus a space)
- Filter APKs by regex: `-unmodified\.apk$`
- Fallback to older releases: on

`obtainium-apps.json` has these entries ready to import (generated by
`python3 scripts/losforgos.py obtainium --repo OWNER/REPO`). I could not test the import
format against a device yet, so treat that file as best effort and check the first import.

Verify a download: the APK's signing certificate SHA-256 is in the repository variable
`CERT_SHA256` and in every release's attestation (`gh attestation verify <apk> --repo OWNER/REPO`).

## How it works

- `apps.toml` pins one upstream commit per app. The `bump upstream` workflow opens a pull
  request on the 1st and 15th of each month when upstream moved.
- `build` fetches the pinned commit, renames the application id, sets a monotonic version
  (`versionCode = YYYYMMDDNN`), applies patches for modified variants, and builds an unsigned
  release APK. This job has no access to secrets.
- `release` (only on `main`, in the `release` environment) signs the APKs, attests them, and
  creates one release per app: tag `<app>-v<version>`, assets `<app>-<version>-<variant>.apk`
  plus a `.sha256`. An app is only released again when its build inputs changed.
- Native libraries and 16 KB alignment are listed in each build log. Memory tagging has to be
  tested on a device; CI cannot do it.

## One-time setup

1. Settings, Actions, General: allow GitHub Actions to create pull requests.
2. Settings, Environments: create an environment named `release`, restricted to the `main` branch.
3. Generate the key on your own machine: `scripts/gen-keystore.sh`, then run the `gh secret set`
   commands it prints. Back the keystore up; losing it forces everyone to reinstall.
4. Run the `build` workflow manually with "release" ticked to publish the first versions.
